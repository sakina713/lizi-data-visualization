# AntV选图逻辑适配

用于新模块或用户要求重新选图。借鉴AntV按问题和数据特征选图、将推荐与渲染分开的思路；以下约束是栗子移动报告的适配规则，不是AntV完整算法或官方评分实现。维护既有报告时保留用户明确决定；参考稿仅提供方法，不能取代当前数据关系与可读性判断。

## 先检查数据，再生成候选

1. 明确读者的问题：比较大小、看变化、看构成、看分布、看相关性，还是追踪流向/处理状态。字段都是百分比，不表示它们可以相加。
2. 识别字段角色：分类N、顺序O、时间T、数值Q，以及主键、单位、分母、统计周期和粒度。数字形式的店号是分类，不作连续坐标；月份须按真实日期排序。
3. 检查类别数、时间点数、系列数、缺失、负数、零值及范围；区分逐条观测与已经聚合的均值/总数。分布图需要样本或可信分桶，不能由一个均值推造分布。
4. 先排除不满足数据条件的类型，再比较可读性、当前参考一致性和渲染能力。候选不必凑满；必要时用表格保留精确信息，缺关键数据则记录缺口。

## 候选与必要条件

AntV官方选图指南将趋势、比较、构成、关系/流向、统计分布等分别映射到相应图表族；其数据接口要求散点有成对x/y、桑基有source/target/value、直方有数值样本。下表结合这些类型补充本报告的使用约束。[官方选图指南](https://github.com/antvis/chart-visualization-skills/blob/master/skills/chart-visualization/SKILL.md)

| 问题 / 数据 | 候选 | 栗子报告中的条件与排除项 |
| --- | --- | --- |
| 一个核心值及比较 | KPI卡、进度条 | 保留单位、环比和基准；无明确目标不画完成进度 |
| 强调本期规模及同比/环比变化 | [变化重点指标卡、两期柱条](period-change.md) | 有可比时期与已确认数值；同比不等于上一周期，箭头不代替趋势，预测与实际分开 |
| N＋Q，比较类别大小 | 柱、条、点图、排名表 | 根据比较任务选择；长名称可考虑横条，需精确查数用表格；普通项统一C1 |
| T＋Q，观察变化 | 折线、时间柱 | 连续趋势可折线，离散周期总量可柱；仅两期用前后比较；缺失断开，不补造连续走势 |
| T＋分类＋Q | 多线、分组柱、堆积柱、小多图 | 比较系列值用共同基线；只有可加总分项才堆积；比较占比变化时才100%堆积，并保留总量信息 |
| 同一总体互斥分项 | 环、饼、100%堆积 | 确认同分母、非负、无重复、总量成立；小项多且难比较时用条/表，不擅自合并“其他” |
| 连续数值样本 | 直方、箱线 | 直方明确分桶边界；箱线需原始样本或已确认分位数/须线定义；只有均值不能画箱线 |
| 同对象两个数值Q＋Q | 散点 | 必须逐对象成对，不能把两个不同人群的汇总拼成点；相关不等于因果 |
| 时段×对象＋Q | 热力矩阵、柱/折线、小多图 | 多对象节奏可优先考虑[时段热力矩阵](time-distribution.md)；轴向和密度按数据适配，精确量级或单对象问题可选柱/折线，不固定复刻参考 |
| 两维类别＋Q，或对象×多指标 | 热力图、数值色块矩阵 | 每格有明确数据，缺失与0区分；单指标全表共用色阶，多指标逐列比较须显式说明范围，遵守[矩阵规范](distribution-matrix.md)；精确查数直接标值 |
| 层级＋非负可加总量 | 矩形树图、层级表 | 真实父子关系，避免父子重复计总；窄屏标签难读时优先层级表，不为面积感强行使用 |
| 起点＋有序增减＋终点 | 瀑布 | 增减能解释起终差额；未核对的独立指标不能串成贡献链 |
| 可追踪阶段及同口径人数 | 漏斗、步骤图 | 核实子集/承接关系；流程顺序固定；步骤计数不可比较时用步骤卡，不造转化率 |
| 来源＋去向＋真实流量 | 桑基 | 有边数据及合理的节点守恒解释；不把独立异常率连到总异常率；当前异常用已确认的anomalyCards |
| 明细记录、状态和结果 | 记录卡、表格 | 逐条理解用卡，跨对象比较/查数用表；保持关键字段、记录数和异常信息 |

面积图只有填充面积确实帮助理解规模/可加总组成时才用，不把普通时间值说成累计。多维数据不默认雷达图；尺度难比较、维度多或精确比较优先时用同轴小多图/表。不同量纲优先分图，不因工具支持双轴就采用双轴。地图只有地理分布本身是问题且有可信位置数据时才考虑，地区名本身不足以要求地图。

## 候选筛选与落地

- 硬条件先行：语义关系、字段、分母、可加总性和数据完整性不满足即排除。外观偏好不能抵消这些条件。
- 软偏好依次考虑：回答当前问题是否直接 → 名称和数值是否清楚 → 静态输出是否无需悬浮 → 当前主题及组件一致性 → 已有渲染器是否支持。没有必要强造数值评分。
- 类别/系列过多时先调整布局、分面或用表格；不把任何库的默认阈值当成删行、截断TopN、合并类别的授权。已有图型的更换需符合用户任务范围。
- 给模块配置留下简短选图理由：问题、字段映射、选用类型、排除候选原因、排序、色彩语义、尺度和必需标签。对比图优先共享尺度，不能逐卡归一制造虚假可比性。
- 渲染前按[图表绘制原则](chart-drawing.md)落地样式；新增散点/箱线等候选不等于现有report.js已支持，需实现适配并验收，不能只改type字段或套无关组件。

例：人才池“在岗活跃/未出勤”符合已确认互斥构成，复用环图并锁定深浅含义；五项异常率回答类型比较问题，不能用桑基暗示构成，复用固定顺序、共同量程的指标卡片柱图；门店月工时只有均值时保留数值/比较图，不画工时分布。
