# 移动端适配：宽度自适应，高度按内容取舍

来自用户历次确认及现有HTML的布局实践。目标是手机上层级清楚、图形紧凑且读数完整，不是将桌面图或Figma整张等比缩小。具体尺寸按数据、文字、容器和图型决定，参考稿的宽高及断点不固化为所有报告的模板。

## 先分配可用宽度

- 以图表所在容器的实际内容宽度为准，扣除页面/卡片内边距、刻度和标签所需空间。嵌套卡片不能直接使用视口宽度或沿用外层卡片的宽度；允许报告设置阅读最大宽度。
- 图形区填充剩余空间，文字区保留可读所需空间。横向空间不足时，优先调整列宽、换行、布局方向或分组，不挤掉基准和数值。
- 等权比较项共享同一列宽规则，柱形、数值、类别名和样本量用同一组列槽；图例的名称、数量和比例用稳定列边界，不能各自独立均分后错位。
- 可复用现有Grid/Flex的弹性列、`minmax(0,1fr)`及`min-width:0`思路，让内容真正可收缩；这些只是实现方式，最终仍须检查实际内容。不要依靠隐藏横向溢出来伪造通过。
- 圆形、Logo及有固定几何含义的图形保持正确宽高比。允许改变柱图绘图区的宽高，但要用同一数据尺度重算，不能把整张SVG或图片任意拉扁。

## 高度可以降低，但必须有依据

将模块拆成“标题/主值、比较信息、绘图区、标签/图例、必要说明”分别排版。文本区按内容自然增高，绘图区可独立调整；不要给整个模块锁定一个高度。

1. **先去无效高度**：收紧空白绘图区、多余上下留白或已经没有内容的占位；保留已确认的关联间距和必要安全边距，不用负边距把独立模块硬贴在一起。
2. **再按信息密度缩短图形区**：少量分类、紧凑指标卡、只需看相对量级的小柱图可以适当降低高度，使手机上不出现窄而高、信息稀疏的卡片。所有可比较项统一调整，保留零基线与共同量程。
3. **根据实际内容确定下限**：轴标签、内部标签、基准和数据差异仍需清楚；缩短后若小值无法辨认、标杆和数值冲突或图形难以区分，就停止缩短，改标签位置、分组或增加高度。
4. **复杂内容允许增高**：漏斗阶段、流向标签、热力行数、排名明细多时，应按内容增高或分段，而不是追求整页固定高度。长图不要求所有卡片同高，也不以一屏容纳全部信息为目标。

降低绘图区高度时保持原始比例：柱高由值和共同量程重新计算，不改变最大值、截断基线或给每项独立归一。不得放大微小值、将零画成可见柱、删时段/排名行来制造紧凑效果。折线重排后注意过扁会掩盖变化、过高会夸大起伏；坐标范围仍按数据和比较任务确定。

## 不同图型的调整重点

| 图型/内容 | 可以如何适配 | 必须保留 |
| --- | --- | --- |
| 柱图、堆积图 | 柱宽/槽距随容器变化，按可读性降低绘图区高度，数值与标签同步布局 | 共同尺度、真实堆积比例、类别对应；不为装字扩大分段 |
| 饼/环图 | 直径按可用宽度与中心文字取舍，图例可移到下方或分列 | 圆形不变形、真实角度、名称＋具体值＋百分比；中心文字放不下时移出而非过度缩字 |
| 指标卡片柱图 | 信息区与短柱区分开，整组共同缩短柱区；同一信息行按最长内容增高 | 相同基线、量程和图形高度，文字不被柱形覆盖；不能按单卡内容分别压缩柱区 |
| 漏斗/流向图 | 给文字独立空间，左右分区或改到图下，阶段间距按文字和图形共同决定 | 指向线与阶段锚点、真实比例和必要比较；复杂图不强行降高 |
| 热力矩阵 | 选择轴向、格子尺寸和分组方式；对象过多可拆成相邻子图 | 共同时间位置与色阶说明、完整对象/时段；不能挤成细条或删掉内部空时段 |
| 排名/费用表 | 优先调整列宽、语义换行、数字对齐；必要时按信息组拆分并重复识别字段 | 行数和字段完整、数值单位不拆散、查数对应明确；高度随行数增长 |
| 案件/记录卡 | 长店名和状态必要时分行，说明自适应增高 | 名称优先、状态次要、关键事实与结果完整 |

## 文字与图形分开适配

- 保持七档字号及用途，不用缩放整页、`transform:scale`或压缩文字来适配。SVG本身缩放时，检查屏幕实际字号；必要时重绘标签或补偿字体大小，不只看viewBox里的数值。
- 标题和长名称按语义换行，关联信息整体换行；金额、计数、百分比及其短单位保持完整，不把数字拆成上下两行。表头均衡换行，同排其他单元格垂直居中。
- 封面紧凑比较可沿用已确认的单行策略和字号例外；长内容允许同项重排，不能为了永远单行删掉行业比较。外侧安全边距及名称/数值对齐遵守原规范。
- 数值标签先按图表主题决定显示范围，再做避让。堆积图可只标主系列；精确查数图例、矩阵和排名不能为降低高度删掉必要读数。
- 基准标签优先保留在既定对应位置；冲突时移开数据标签或隐藏冲突的普通刻度，不移动基准的真实值。换行后重新检查上下左右间隙，不能让线穿字。
- 同组卡片的名称、数值、比较等信息行共同对齐，长名称使该行整体增高；下方绘图区继续对齐。图例从并排转为两行时仍保持同项分组，不能串到下一类。

## 布局需要随真实内容更新

- 初次渲染、字体就绪、数据/模块变化和可用宽度变化后，重算依赖尺寸的标签、图形、指向线与基准避让。容器宽度变化不一定伴随窗口resize，布局逻辑应覆盖真实使用场景。
- 测量使用最终可见元素和已加载字体，不依赖旧截图坐标或隐藏旧图层。SVG文字增大后要检查viewBox和裁切范围，不能只改字号却裁掉底部月份。
- 重新布局应从源数据与当前尺寸计算，不在上一次已变形结果上继续缩放，避免反复切换宽度后位置漂移。
- 当前HTML已有弹性列、字体就绪/窗口变化后重新布局、柱顶标签避让、SVG文字缩放补偿及同组信息行对齐等做法。按最终CSS层叠读取，早期样式可能已被覆盖；现有固定高度和旧SVG不代表所有内容已实现完整自适应。
- 本页是适配规则，不是已经改造运行器的声明。使用现有组件前确认其能力；新增自适应行为要实际实现和验收，不能只写配置或给容器加`width:100%`就宣称完成。

## 验收宽度、密度与视觉平衡

当前移动报告检查320、375、393、430px。记录视口宽度和实际内容宽度：若报告有最大宽限制，宽视口下内容可能仍较窄，不应声称图表已经在更宽内容尺寸验证。若交付要求真正全宽，需要另外检查该内容宽度。

- 看局部截图而不仅检查溢出：重点是否清楚、窄图是否过高、留白是否有效、降低高度后数据差异是否仍可辨。
- 检查长名称、长比较说明、较大金额/计数、极小值、零值与缺失、不同类别数；具体覆盖与本次变更相关，不机械重复无关测试。
- 确认无裁切/遮挡、无连线穿字、无数字断行、无图例错位；圆形仍为圆、共同比例未改变，同组信息行及基线对齐。
- 等待字体、资源和重新布局完成再导出。移动HTML允许纵向阅读，但必要信息不能藏在横向滚动、悬浮或点击之后；静态图片需完整呈现内容，长图需拆分时按完整模块拆，保留顺序。

统一视觉语言并不意味着统一每张图的尺寸。合适的结果是：宽度适应容器，高度服务信息量，重点更容易看到，必要数据仍然完整。
